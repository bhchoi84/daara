프리미엄 회원 관리 시스템 설계

Vercel KV(Redis) 기반 서버 측 프리미엄 관리

목표

localStorage 기반 → Vercel KV 서버 측 관리로 전환

해결되는 문제

  • 위변조 방지 (개발자도구 조작 차단)
  • 기기 간 프리미엄 상태 공유
  • 서버 측 사용량 검증

현재 문제점

  • localStorage만으로 프리미엄 관리
  • 브라우저에서 직접 수정 가능
  • 기기 변경 시 프리미엄 소실

사용자 식별: 이메일 기반

왜 이메일인가?

  • 유지보수 비용 0원 (SMS 인증 비용 없음)
  • 개발 기간 1~2일
  • 기기 간 공유 가능
  • 향후 마케팅(프로모션) 활용 가능

무료 vs 프리미엄 비교

항목 무료 프리미엄 ★
일일 타로/운세 상담 3회 20회
손금/관상 분석 1회/일 5회/일
광고 있음 없음
답변 깊이 간결 (3~6문장) 상세 풀이 (8~12문장)
AI 모델 Haiku Haiku (동일)

Vercel KV 데이터 구조

premium:{email} → {
  plan: "1day" | "30day",
  expiry: "2026-04-27",
  paymentKey, orderId, approvedAt
}

usage:{email}:{date} → {
  count: 5,
  palm: 1
}

TTL 자동 만료: 1일권 24h, 30일권 30d, usage 24h

API 흐름

현재 (위변조 가능)

브라우저 → /api/chat → Anthropic 프리미엄: localStorage만 체크

변경 후 (서버 검증)

브라우저 → /api/chat + email → KV 검증 → Anthropic

프리미엄 → 상세 프롬프트 | 무료 → 간결 프롬프트 | 한도초과 → 403

API 엔드포인트

POST /api/chat 수정 + email, KV 검증, 프롬프트 분기
POST /api/payment-confirm 수정 + KV에 프리미엄 저장
GET /api/user-status 신규 프리미엄 여부 + 잔여 횟수 조회

필요 환경변수

기존: ANTHROPIC_API_KEY, TOSS_SECRET_KEY
추가: KV_REST_API_URL, KV_REST_API_TOKEN

Vercel Dashboard → Storage → KV 생성 후 자동 연결
